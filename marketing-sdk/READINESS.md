# Production readiness and consumer qualification

This SDK supports the bounded native adapters and host authority model in
[the integration guide](README.md). Local regression evidence does not establish
live account permissions, billing, delivery or a consumer's deployment readiness.

## Consumer contract

Node 22.23.1 (22.x), normal npm Git `prepare`, and the matching lockfile are required.
Install the public HTTPS repository at the release's full 40-character SHA.
Keep build tools enabled during preparation; `npm ci --include=dev` builds this
repository. TypeScript consumers of React components also need `@types/react`.
Use only `/core` (or the root) and `/react` in browser code. Store, provider ports,
credentials, connection strings and reference host imports belong on the server.

`Store.postgres`, `MarketingServer.unconnected`, `saveDraft`, `workspace.drafts`
and `bindExternalPrincipal` retain their existing contracts. The trusted bootstrap
actually exported by the inspected 0.1.3 source is `provision` from `/reference`;
that source has no `initializeWorkspace` export. Do not assume an unimplemented
initializer. See [draft integration](DRAFTS.md) for provisioning, current host
identity/role binding, revocation, immutable retry receipts and optimistic edits.
Unconnected local drafts require no provider account, grant or credentials.

No migration or public command change is needed for this cleanup. mysql2's
`jsonStrings: true` preserves the Store's serialized-JSON contract on MariaDB.
The SQL layer and schema migrations remain the existing ones. PostgreSQL requires
direct/session-pooled connections; SQLite remains a local regression harness.

Consumers should account for these stricter boundaries:

- `inspectMedia(bytes, kind, expectedMime?)` accepts an optional MIME assertion.
  Image signatures must be PNG, JPEG or WebP before sharp is invoked. Inputs must
  be nonempty and below 100 MiB, dimensions at most 16,384, and images at most
  40 million pixels (including the reported page count). Native image decoding
  has a 10-second timeout and rejects corrupt/truncated data. No global sharp
  settings are changed. Video inspection requires local ffprobe, retains the
  H.264/MP4, 120-second ceiling, adds dimension/pixel bounds and restricts protocols
  to local files. Video probing is not a full decode of every frame.
- The service inspects generated bytes from all generation ports before retention
  and inspects retained campaign media before provider preparation. MIME claims
  must match; dimensions/duration come from inspection. Invalid output leaves a
  submitted job unknown, with its retained request ID and retry fence intact.
- Generation reconciliation now rejects expired/revoked grants before provider
  access. Restore legitimate authority through trusted host provisioning before
  reconciliation; never use a new job/key to bypass an unknown outcome.
- Native provider/SDK exceptions become stable `DomainError` codes, without raw
  provider bodies, request configuration or native decoder diagnostics. Existing
  domain validation codes remain available. A transport error is never evidence
  that a write did not happen. Use the durable operation/job and reconciliation.

Authentication still permits empty passwords and enforces 10 login attempts per
60 seconds using the database transaction guard. Success counts in the same
window. No additional password complexity, IP lockout, account lockout or MFA
policy is introduced. Embedding hosts authenticate their own sessions before
every SDK call; the SDK independently checks current membership/disabled state.

## Dependencies and verification

Exact pins are sharp 0.35.5 and mysql2 3.24.5; the build lock includes
source-map-js 1.2.2. These address the reviewed
[libvips](https://github.com/advisories/GHSA-f88m-g3jw-g9cj),
[libheif](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c),
[mysql2 compressed protocol](https://github.com/advisories/GHSA-rgwj-5xj2-c3m3),
and [source-map-js](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) advisories.
The Linux x64 qualification used sharp's prebuilt 0.35.5 addon with libvips
8.18.7 and libheif 1.23.5. Consumers using custom system libraries must inspect
their actual `sharp.versions`; a package version alone does not identify them.

Run these checks sequentially after the last source change:

```sh
npm ci --include=dev
npm run build
npm run typecheck
npm test
npm run test:postgres
npm run test:mariadb
npm run test:browser:mariadb
npm run test:consumer
npm audit --include=dev
node -e 'console.log(require("sharp").versions)'
```

The DB runners use fresh private socket-only databases, never ambient application
credentials. PostgreSQL needs initdb/pg_ctl; MariaDB needs mariadbd and
mariadb-install-db (an extracted installation can set
`MARKETING_TEST_MARIADB_BASEDIR` plus PATH/library paths). Set TMPDIR to a private
writable short path for Unix sockets. The MariaDB suite asserts compression is
enabled and round-trips binary/Unicode through the production prepared-query
layer. Both runners discover all test files so new regressions cannot be omitted.
Browser tests need Playwright Chromium and use only the disposable fixture host.

The suite covers real persistence/migrations/rollback/restart, project and user
isolation, revoked sessions, concurrent rate limits, local drafts, request-key and
revision races, executor loss, partial provider writes/unknown outcomes, media
validation, reporting and public HTTP commands. External provider boundaries use
labelled fixtures or intercepted HTTP; no live posts or paid generation are run.
Database-specific tests are explicitly skipped on other dialects.

`test:consumer` projects candidate package files into a fresh temporary consumer
with independent dependencies, compiles all public entry points with strict
TypeScript and `skipLibCheck: false`, imports runtime exports/CSS, exercises a real
SQLite draft round trip, and checks the browser module graph excludes server code.
This verifies package contracts without pretending the uncommitted source has
been published or installing a local SDK dependency into an application.

## Release handoff

Handrail's native pipeline owns the version bump, commit and push. After it
publishes, record the actual package version and public full SHA, then run:

```sh
npm run test:consumer -- "$SDK_SHA"
```

This mode installs the public Git dependency, runs preparation, checks the pinned
lock and performs a clean consumer `npm ci`, compile, imports and runtime checks.
npm 10 can canonicalize an explicit HTTPS Git dependency's `resolved` lock entry
to SSH. Keep that entry on the same repository/SHA with `git+https://` and verify
`npm ci`; the qualification script performs this normalization explicitly.
Never substitute a branch, tag, registry, file or tarball dependency.

The baseline Git-install check at
`cdda436654420632df237223842f4dd20fcc56d7` is separate from candidate qualification;
it cannot qualify the unpublished changes. The Preview coordinator must consume
the final published SHA/lock, wire its real authentication and drafts, and qualify
its own application. Live provider acceptance and deployment remain separate.
