# Campaign prerequisite check candidate · 2026-10-07

This extends the reviewed [complete journey](COMPLETE-JOURNEY.md). The evidence
index is `artifacts/native-preflight-7ed6998b/receipt.json`. Independent review is
still required; this is not whole-product acceptance, actual account eligibility,
publication qualification or Ready.

The authenticated public `checkCampaign` command accepts only `campaignId`,
`expectedRevision`, `expectedGrantRevision` and `requestKey`. `campaignCheck`
reads the latest attempt, or an original attempt by request key. The core client,
server dispatcher and default Launch readiness use the same contract. An editor
still needs existing prepare-scoped connection access. Checking creates no grant,
approval, reservation, upload or advertising object. It supplies prerequisites for
attempting separately authorized paused preparation. Ad acceptance, hierarchy
readback, policy review, delivery, spending authority and attribution remain later
or separate facts.

The initial producer supports Meta v26 ordinary single-image traffic with a
lifetime budget and exact current first-party inquiry Tracking configuration.
Local material, plan and budget validation, asset ownership, actual retained-byte
hashes and decoding, destination snapshot, schedule/currency/timezone, purpose and
outcome are checked. A Tracking QA pass is neither required nor treated as provider
capability or production coverage. Required provider conversions, Meta daily,
video, strict targeting, Employment and unsupported provider tuples remain blocked.
Connections supplies publishing identity choices, not a complete targeting
catalogue. Selected languages/professional/strict options still require that next
catalogue qualification gate; ordinary Meta success does not qualify them.

`NativeProvider.inspectPrerequisites` composes current Connections discovery,
account context and settings reads with the native account/billing/Page inspection.
It uses the read-only credential method, not token refresh or circular `verify`.
Complete bounded account/Page enumeration rejects duplicate/conflicting rows and
incomplete continuations. Required scopes, account roles, active status, a present
funding-source signal, exact currency/timezone and Page/Instagram relationship must
all be observed. Meta requests reject redirects. The check's private transport
boundary additionally permits only GET requests at the fixed versioned origin.
These reads cannot promise later upload/create acceptance or actual delivery.

Attempts live in separate `campaignCheck` Store records. A campaign-local current
pointer advances under the existing SQL guard; a late older completion becomes
stale and cannot replace newer evidence. Same-key submissions return their original
attempt without repeating HTTP. Status reads never resume abandoned work; after
the bounded read deadline it is incomplete and an explicit new check is required.
Failures never renew expiry. Historical attempts and existing operation/unknown
object/exposure records remain unchanged.

Proof binds project/campaign/revision and prepare-prerequisite purpose; grant and
revision/account/identity/manager custody; exact material/plan, asset records and
actual byte hashes; destination and Tracking/outcome configuration; API/adapter
contract; connection/configuration/policy/custody and current actor/original access
sessions. Normalized checked facts and local receipt references are retained.
Private custody/authority fingerprints never enter browser responses. Expiry is
at most two minutes and capped by grant, credential, connection, session and
campaign validity. Current policy/configuration inspection remains mandatory.
Grant revision is never changed when proof is appended.

Unlocked asynchronous reads recheck authority and bound data before and after.
Final guards acquire session authority, then source authority, then Store; no
provider HTTP or image decode occurs under those guards. Native dispatch consumes
current proof before verification and again before every write. Paused preparation
and activation keep their existing plan, readback, actor, lease, packet and budget
safeguards. Activation consumes preparation prerequisites in addition to its own
exact human authorization; the check does not authorize activation. Legacy
non-Connections capability receipts retain their old adapter behavior; they are
not copied into or accepted as this new SDK-owned proof.

Default readiness exposes checking, ready for preparation, blocked, incomplete and
stale states, last-checked time and corrections. Changed material/access shows
Check updated campaign. Cancel, navigation and disposal fence UI repaint while
server history remains available through explicit status reads. No automatic OAuth
escalation or new polling was added.

Qualification uses existing real SQLite and isolated socket-only PostgreSQL
harnesses, independent connection/process races and a separate public-export
consumer projection with external SQL sessions and Agent absent. The native HTTP
fixtures are injected only at the supported private fetch boundary. No campaign,
metric or capability-evidence rows are inserted to prove the joined happy path.
The consumer's source/billing/pricing/permission facts are synthetic host glue,
not actual provider eligibility or host spending authority. Exact public HTTPS
Git/full-SHA installation remains open under the stopped publication gate.

Source/runtime/consumer manifests, HTTP traces, identity chain, request timelines,
local 1440/390/320 screenshots, actual failures and precise remaining checks belong
to the receipt. Existing rapid/continuous throttling and recovery artifacts remain
historical evidence. The new happy journey and added UI interactions are counted
separately. Preview/all-mounted budget, native/device/full accessibility/dot review,
actual host adapters, direct-provider spending profile, persistent/unattended
permissions, migrations and publication remain separate open gates.
